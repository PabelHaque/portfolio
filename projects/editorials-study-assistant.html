Autonomous Exam-Study Intelligence Platform

Candidates for Bangladesh's civil-service and bank written exams need current-affairs material mapped to a syllabus — and drown in editorial columns that are interesting but irrelevant. This pipeline crawls the sources, scores every article 0–100 for exam readiness through a deterministic taxonomy plus an LLM gate, discards what does not make the cut, and serves the rest through an 18-page study workspace. It runs on free-tier and local models by default, and will not make a paid API call unless explicitly told to.

The problem

The raw material for these exams is public: newspaper op-eds, business analysis, global geopolitics coverage. The difficulty is that maybe one article in ten is usable, and finding it costs an hour a day of the exact attention that should be going into studying.

A naive scraper makes this worse rather than better. It delivers a firehose — lifestyle pieces, sports columns, personal essays, and foreign coverage with no bearing on the syllabus — and the filtering problem simply moves downstream. The value is entirely in the discarding.

The relevance gate

Deterministic taxonomy first, LLM second.

Scoring runs in two passes, in that order and for a reason. A deterministic topic taxonomy maps each article against syllabus themes; only then does the LLM assign a strict 0–100 exam-readiness score. Articles below the threshold never enter the main study queue — they go to a rejected-article log instead, so a bad filtering decision is auditable rather than invisible.

Putting the cheap deterministic pass first is not only a cost decision. It means the model is scoring within a known topic frame rather than inventing one per article, which is what keeps the scores comparable across a corpus that grows nightly.

The rule that makes foreign coverage useful International sources are held to a stricter bar than local ones: the model must identify a concrete Bangladesh connection before an article is kept. Each surviving global article stores that reasoning in its own fields — the issue tags, the Bangladesh link analysis, the impact points, the response strategy — so a candidate gets the argument, not just the headline. Without that rule, the global layer would fill the queue with well-written articles nobody can use in an exam answer.

The detail I would defend in an interview

A model router with a real fallback chain — free and local tiers first.

This system exists in a context where a monthly API bill is a genuine constraint. That shaped the architecture rather than being patched on afterwards.

Every LLM call goes through a shared router with an ordered fallback chain. It tries free-tier hosted open-weight routes first, then a second independent free-tier provider serving the same open-weight model, then local models. It advances down the chain on any of: a rate limit, a daily quota exhaustion, invalid JSON in the response, an unavailable model, or a local server that is simply not running.

  • Paid routes are off by default behind an explicit opt-in flag. Cost cannot escape by accident — the expensive path requires someone to choose it.
  • Provider independence. The second free-tier provider serves the same open-weight model, so exhausting one daily quota degrades throughput, not output quality. Neither provider is required for the other to work: with only the second key present, the router picks it directly.
  • Invalid JSON is a routing signal, not a crash. Treating a malformed structured response the same as an outage is what keeps an overnight crawl from dying at 2am on one bad generation.
  • Named presets for best-quality, fastest, and Bangla-capable routing, so the operator picks an intent rather than a model identifier.

Handling a corpus that predates its own scoring

Relevance scoring did not exist in the first version, so there was already a body of articles with no score. Deleting them would have discarded real content; scoring them as zero would have hidden it; pretending they had been scored would have corrupted the comparison.

Instead they are explicitly marked legacy and backfilled at a neutral value until a rescore pass reaches them — with rescore_articles.py recalculating historical scores against the current gate. The state is visible in the data rather than papered over, which is the version of this decision you can still reason about a year later.

Beyond the crawler

The platform ingests past exam questions from three directions, because no single one is sufficient: structured CSV import for questions already transcribed, online discovery that downloads linked PDFs and images from public sources, and an OCR path that prepares scanned papers for review using local tools only. On top of the corpus sit model answers, an answer rubric, practice sets, a question workbench, a prompt lab for iterating on the scoring prompts themselves, and a source-health page for spotting a feed that has quietly stopped returning anything.

Long-running work — crawls, rescores, ingestion — goes through an app-safe background job runner rather than blocking the interface, so the workspace stays usable while a crawl is in flight.

Outcome

A daily current-affairs workflow that used to cost an hour of triage now arrives pre-filtered, syllabus-mapped, scored, and exportable as a study pack — running on free and local models, with the paid path switched off.
