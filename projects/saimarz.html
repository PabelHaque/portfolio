SaiMarz — Large-Workbook Join Tool

The job people do with VLOOKUP across hundreds of thousands of rows, as a tool colleagues install themselves and run offline. Five steps down the left-hand side, and a check that runs before anything is written. The problem

Two monthly exports, each around 730,000 rows by 95 columns, and a question that needs columns from one attached to rows of the other. In a spreadsheet that is a lookup formula dragged down three-quarters of a million rows: slow enough to freeze the machine, and wrong in ways that leave no trace.

The silent failures are the reason this exists. A key that is blank on a quarter of the rows can never match those rows, but the result still looks complete. A key the lookup file repeats means "take the first match" is choosing one of several arbitrarily, and nothing says so. And a member ID written as a number loses its leading zero, so 0012345 becomes 12345 — which is still a plausible-looking identifier, and matches nothing.

What I built

Five steps, in order, with the destructive one last.

The detail I would defend in an interview

The tool tells you what your key will cost before you use it.

Under the key picker, one sentence: how much of the column is filled, how many keys the lookup file repeats, and the highest match rate that is therefore possible. A key that is blank on a quarter of the rows is capped at 75% before the join has run, and a repeated key means the tool is picking arbitrarily among candidates.

Neither fact is visible in a spreadsheet, and both change what a careful person would do. Putting them on screen at the moment of the decision, rather than in a log afterwards, is most of the value of the tool. There is also a comparison view that scores every candidate column, for when the obvious key turns out to be the wrong one.

Keeps a zero a zero When a column holds digits stored as text with leading zeros — a member ID, a staff ID, a phone number — it stays text, and the tool says so on screen. Writing 0012345 as a number produces 12345, which still looks like a valid identifier. That is the difference between a join that fails visibly and one that fails silently.

Three more decisions

  • No network calls at any point. No telemetry, no update check, nothing. It works with the network cable pulled out. The activity log records file names, sheet names, column names and timings, and never the contents of a row — so the log is safe to send when someone needs help.
  • Every output carries its own provenance. Each workbook it writes includes a metadata sheet recording which files were merged, their fingerprints, the key, the join settings, the match rate and the version that produced it. A result found on a shared drive months later can be traced back to its inputs.
  • It has to install without help. Per-user installation, so no administrator password, and everything bundled, so no runtime to install first. The documentation tells people the unsigned-installer warning is coming and what to click, because a tool nobody can install is not a tool.

Outcome

Colleagues join two very large workbooks themselves, offline, and see the cost of their key before they commit to it. On a measured pair of real exports — 731,771 rows by 95 columns joined to 723,121 by 95 — reading each file takes about two minutes once and is cached thereafter, the pre-flight check about thirty seconds, and the write under a minute.
