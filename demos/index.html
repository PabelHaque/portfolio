System demos

Working simulations of systems I designed and built at a 400-branch microfinance institution in Bangladesh (2024–2026). Each one reproduces the real screens and business rules with invented data. Open any card; a guided tour inside each page walks through the main flow in about three minutes.

Field-Staff Target System

Splits every branch target across its officers by a weighted formula so the parts sum exactly to the whole, with validation, a run state machine and a full audit trail.

Django · ReactAllocation engineAudit log

Production: ~18,000 weekly targets for 2,600 officers in 409 branches, live since July 2026.

Open simulation

SaiMarz

Offline desktop tool that joins two 730,000-row weekly workbooks and reports the duplicate-key conflicts VLOOKUP hides, with a provenance sheet in every output.

PySide6 · DuckDB · PolarsDesktop

Production: about 46 seconds per run, replacing a crash-prone 20–30 minute process.

Open simulation

MFS Branch Wallet Portal

bKash / Nagad merchant-wallet onboarding for branch offices: bilingual forms, a 13-state maker-checker workflow, account change requests and generated provider packs.

DjangoBengali / EnglishWorkflow

Production: 731 branch users, 189 registrations, median 0.8-day verification, live since June 2026.

Open simulation

Transfer Eligibility Control Tower

Checks member transfer requests against loan positions read from the core ERP and flags overdue members moved between officers, the pattern that hides portfolio at risk.

Streamlit · PlaywrightERP automation

Configured for 568 branch offices; every check logged.

Open simulation

Special Permission Register

Reads a WhatsApp group export, extracts loan special-permission, rebate and waiver applications, validates members against the ERP and builds audit dashboards. Reads only; never sends.

Flask · PlaywrightBilingual parsing

Production: 257 applications across 141 branches, 12 months of history.

Open simulation

Special Rebate Automation

From zonal e-mails to a verified SMS list: extracts member rows from attachments, verifies in the ERP, applies three-tier eligibility, removes ineligible rows with reasons and drafts the ICT hand-off.

Outlook COM · PlaywrightRules registry

Production: 66 members processed, 4 ineligible rebates caught before payment.

Open simulation

Document Extraction Engine

NID card to KYC reconciliation: barcode first, OCR fallback, member resolution by NID then name and date of birth, and a review queue for mismatches. Unknown stays unknown.

Python · OCROffline

4 of 5 planned stages built; nothing leaves the machine.
